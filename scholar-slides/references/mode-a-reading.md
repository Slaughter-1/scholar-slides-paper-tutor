# Mode A 阅读视图与 Paper-Tutor 交接

Mode A 的目标是让读者先形成可靠的整体模型，再决定是否深入某个公式、图表或实验。它不是把摘要换成更多列表，而是把问题、机制、证据和边界连成一条可复述的主线。

## 生成顺序

1. 核对论文身份、源 PDF 和当前项目；不合并不匹配项目。
2. 读取 digest、候选审阅内容和可用证据，保留 Paper Fact、Tutor Explanation、Tutor Analysis 的边界。
3. 编写项目内 `reading-view.json`，其事实单元要带 `claim_type`、`availability` 和 `evidence_refs`；论证节点也必须带这三个字段。优先引用已有 Evidence ID；没有 ID 时使用 `p. N, Section/Figure/Table` 这类可解析的真实页码定位，或使用 `digest.json#/...` JSON Pointer，不伪造 ID。运行时会检查页码范围、pointer/ID 是否存在，并拒绝无法解析的自由字符串。凡是依据项目 `digest.json` 编写的视图，同时把该文件和实际源 PDF 列入 `source_bindings`，并记录当前 SHA-256。
4. 运行 `user_documents.py paper-analysis`，让 runtime 校验视图并生成 `paper-analysis.md`。
5. 检查输出是否按视图的 `language` 渲染（默认 `zh-CN`，可用 `en-US`）、有输入→输出机制、决定性证据、带角色与状态的论证链、关键术语解释和结论边界。首屏只压缩主线；第二节解释缺口如何导向设计选择，不重复首屏句子。

运行时只校验和渲染，不翻译、不补事实、不把缺失的提取结果升级成作者未报告的结论。视图绑定的源文件发生变化时应拒绝渲染，保留已有可用输出。

## 首轮分析结构

输出按以下七部分组织：

1. **30 秒看懂**：问题、缺口、关键做法、主要发现、适用边界。
2. **问题与核心思路**：旧做法哪里不够，以及作者改变了哪个关键点。
3. **它具体怎么做**：每个主要步骤写作用、输入、输出、必要性；不要用同一段话同时充当方法概览和方法拆解。
4. **证据如何支持结论**：对 2–4 个决定性实验说明问题、比较、指标、结果、能支持什么和不能支持什么。
5. **作者如何组织论证**：把背景→缺口→Insight→方法→证据→结论串成论证链；它与方法执行流程分开。
6. **关键术语与前置知识**：只选会阻碍理解的概念，给出白话定义、本文作用和常见混淆。
7. **贡献、局限与值得追问的问题**：作者明确贡献、证据边界、读者分析和一个具体追问分开。

Benchmark 论文必须保留 Motivation、Capability、Task、Input / Output、Dataset、Environment、Models、Agent、Baseline、Metric、Result、Scaling、Failure、Validity、Conclusion、Research Gap 十六项。首轮分析用主线和证据讲清它们，Paper-Tutor 再用概览表和正文分层展开；不因表格精简而删除字段。

## 术语规则

不要按全大写、连字符或出现顺序机械选词。优先选影响问题定义、核心机制、实验比较或结果解释的概念。首次出现使用“中文解释（英文术语）”；集中表使用以下列。术语行必须把 `claim_type` 和 `availability` 转成读者可见的标签，不能让待核实定义看起来像已确认知识：

| 术语 | 一句话理解（含状态） | 在本文中的作用 | 常见混淆 |
| --- | --- | --- | --- |
| 由 Codex 根据证据填写 | 白话定义 | 本文具体作用 | 需要避免的误解 |

禁止输出“保留论文原文术语，结合对应方法或实验语境理解”等无定义占位句。论文自定义含义要有论文定位；通用背景知识标为解释，必要时给出外部来源，不能冒充作者陈述。

## 与 Paper-Tutor 的交接

- Scholar-Slides 负责身份、事实、证据定位、研究逻辑和真实确认状态。
- Paper-Tutor 负责前置知识、白话解释、最小例子、易混淆点、阅读迁移和研究追问。
- Tutor 可以读取匹配的 Scholar-Slides 分析和视图，但不写回 digest、候选、checkpoint 或 Mode B。
- 用户同时要求分析和教学时，CKPT-1 待确认状态要如实显示，但不阻断已授权教学；只有演示生成继续遵守 CKPT-1/CKPT-2 审批。
- 局部追问只解释相关内容；不要重跑完整论文或自动生成全套阅读资产，除非用户明确要求。

## 交付前检查

- 读者能在首段说出问题、做法、主要发现和边界。
- 方法步骤有输入和输出，且不与论证链重复。
- 每个关键数字带任务/数据、指标、比较设置和证据定位。
- 关键术语不只是列名，而是有定义、本文作用和混淆提醒。
- `Paper Fact`、解释和分析可区分；缺失证据写明缺口。
- CKPT 状态真实；没有代批、没有向 Mode B 写入教学文本。
